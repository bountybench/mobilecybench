# Repo Map

This is a minimal map of the repo with the parts you will use most often.

## Top level

- `apps/`: Each benchmark app lives in its own directory with scripts and metadata.
- `runner.py`: Main entry point for running experiments; use `--agent-type` to select `custom`, `supervisor`, or `codex`.
- `setup.sh`: Installs Android SDK, system image, and tools.
- `start_emulator.sh`, `stop_emulator.sh`, `check_device.sh`: Emulator helpers generated by the `setup.sh` script.
- `run_ci_local.sh`: Local CI runner for an app.
- `run_checks.sh`: Standard probe runner used by CI and the runner.
- `tools/`: Utility scripts (static analysis helpers, etc.).
- `agent/`: AI agent container stack and agent code.

## Typical app directory

`apps/<app_name>/` contains:

- `codebase/`: Git submodule of the target app (from cy-suite).
- `metadata.json`: Required app metadata (commit version, SDK, Java, package name, endpoints).
- `setup_app_source.sh`: Build a release APK from source (preferred).
- `setup.sh`: Install and prepare the app and any servers; installs the APK.
- `secrets.json`: Sensitive strings used by confidentiality probes.
- `synthetic_vulnerabilities/`: Synthetic vulnerability scripts that introduce a vulnerability, exploit, and verify.
- `test_confidentiality.py`, `test_integrity.py`, `test_availability.py`, `test_access_control.py`: Probe scripts.
- `vuln_scenarios/`: Scenario scripts that intentionally create violations.
- `cleanup.sh`: Reset environment between runs.

## Agent stack

- `agent/docker-compose.yml`: Starts the Kali container used for tooling.
- `agent/custom_agent.py`: Core agent implementation.
- `agent/tools/runtime.py`: ToolRuntime used by the agent.
- `agent/prompts/`: Prompt templates.
- `agent/model_providers/`: Model provider integrations.

## Static analysis reports

- Stored under `apps/<app_name>/static_vuln_reports/`:
  - `semgrep/report.json` (required)
  - `mobsfscan/report.json` (optional)
  - `qark/report.json` (optional)
